# Бинарный файл записей

Необходимо реализовать функции записи и чтения списка студентов в бинарном формате,
а также функцию, которая изменяет одно поле записи прямо в файле, не переписывая
его целиком.

Структура `Student` дана в заготовке и **НЕ** изменяется (оператор `==` по умолчанию,
C++20, нужен тестам):

```c++
struct Student {
    std::uint32_t id = 0;
    std::string name;
    std::int32_t score = 0;
};
```

## Формат файла

Все целые числа записываются в порядке _little-endian_ (младший байт первым)
независимо от платформы, на которой работает программа.

Заголовок:

| Поле | Размер | Значение |
|---|---|---|
| сигнатура | 4 байта | символы `PSDS` |
| версия | `uint16` | `1` |
| количество записей | `uint32` | `N` |

После заголовка подряд идут `N` записей:

| Поле | Размер |
|---|---|
| идентиификатор `id` | `uint32` |
| длина имени в байтах | `uint16` |
| имя из `name`| байты строки, без завершающего нулевого символа |
| баллы `score` | `int32` в дополнительном коде |

Пример: список `{{1, "Ann", 95}, {258, "", -1}}` записывается так (33 байта,
шестнадцатеричные значения):

```txt
50 53 44 53  01 00  02 00 00 00
01 00 00 00  03 00  41 6E 6E  5F 00 00 00
02 01 00 00  00 00  FF FF FF FF
```
- пробелы и переводы строк добавлены только для наглядности: первая строка -
  заголовок, следующие - записи, двойными пробелами разделены поля. В файле байты
  идут подряд без каких-либо разделителей

Имя может быть пустым и может содержать любые байты, в том числе `'\0'` и символы
UTF-8: длина имени `"Иван"` равна 8 байтам.

## Функции

Сигнатуры функций необходимо написать самостоятельно по описанию ниже и тестам.

- `WriteStudents` - принимает поток вывода и список студентов, записывает файл,
  начиная с текущей позиции потока. Возвращает признак успеха: успех, если поток
  после записи в порядке. Если имя хотя бы одного студента длиннее 65535 байт,
  возвращает неуспех и **ничего** не записывает
- `ReadStudents` - принимает поток ввода и список студентов, в который нужно
  поместить результат. Читает файл, начиная с текущей позиции потока, и заменяет
  содержимое списка прочитанными записями. При ошибке список **НЕ** меняется.
  Возвращает признак успеха. Неуспех, если:
  - сигнатура или версия не совпадают
  - данные закончились раньше, чем прочитаны все `N` записей
  - после последней записи в потоке остались лишние байты
- `CountStudents` - принимает поток ввода, читает **только** заголовок, начиная с
  текущей позиции, и возвращает количество записей `N` или `-1`, если заголовок
  прочитать не удалось или он неверный. Возвращаемое значение должно вмещать любое
  количество записей, допустимое форматом. После успешного вызова позиция чтения
  стоит сразу за заголовком
- `UpdateScore` - принимает поток, из которого можно и читать, и в который можно
  писать, `id` и новое значение `score`. Ищет с начала файла первую запись с этим
  `id` и перезаписывает **только** 4 байта её поля `score`. Возвращает признак
  успеха: успех, если запись найдена и изменена, неуспех, если записи нет, заголовок
  неверный или файл обрывается раньше, чем заканчивается проверяемая запись. При
  неуспехе данные **НЕ** меняются, в том числе **НЕ** меняется их размер.
  Требования к функции:
  - перед поиском функция сбрасывает состояние потока: до вызова поток может быть в
    состоянии ошибки или в конце данных
  - имена записей **НЕ** читаются в память, их нужно пропускать перемещением позиции
    чтения
  - перед записью нужно убедиться, что все 4 байта поля `score` есть в файле
  - после успешного вызова поток в состоянии `good()`

Функции должны работать с любым подходящим потоком: тесты передают как строковые,
так и файловые потоки, открытые в бинарном режиме.

## Примечание

- Порядок байт нужно задавать явно: записывать число по одному байту через сдвиги
  и маску (`(value >> 8) & 0xFF`) и так же собирать его при чтении. Запись числа
  через `reinterpret_cast` его адреса **НЕ** подходит: результат зависит от порядка
  байт платформы (на x86 и ARM тесты пройдут, на big-endian - нет)
- Байт, прочитанный в `char`, может оказаться отрицательным (знаковость `char`
  зависит от платформы). Перед сдвигом его нужно привести к `unsigned char`
- Преобразование `std::int32_t` в `std::uint32_t` выполняется по модулю 2^32.
  Обратное преобразование значения больше `INT32_MAX` до C++20 давало результат,
  определяемый реализацией, а с C++20 тоже выполняется по модулю 2^N. То же относится
  к `static_cast<char>` от значений больше 127
- Помните, что у `std::fstream` одна позиция на чтение и запись, а у
  `std::stringstream` - две раздельные (`seekg`/`tellg` и `seekp`/`tellp`).
  Решение должно быть корректным для обоих потоков
- `seekg` за конец данных у файлового потока может завершиться успешно, а у
  строкового - нет. Ошибка обнаружится при следующем чтении
- Сколько байт реально прочитано методом `read`, сообщает `gcount()`
- Тесты создают временные файлы в `std::filesystem::temp_directory_path()`
